## 1. نظرة عامة

«بيان» نظام متكامل لإدارة دورة البيع والمخزون في شركات الحديد والبويّات. يعمل عبر ثلاث واجهات:

| الواجهة | المستخدم | الوصف |
| --- | --- | --- |
| **لوحة الويب** | المكتب، الإدارة، المحاسبة، المخازن، المالك | شاشة كاملة على المتصفح لكل الوظائف والتقارير |
| **تطبيق المندوب** | مندوب المبيعات (أندرويد) | يعمل **بدون إنترنت**، يزامن البيانات لاحقاً |
| **لوحة المشرف العام** | مدير البيئة (SaaS) | إدارة الشركات والميزات العامة |

### مفاهيم أساسية

- **بيان الأسعار (BP-):** هي الفاتورة. تمر بمراحل: **مسودة ← معتمد ← (مرحّل للأرشيف)**، وحالة جانبية **ملغي**.
- **الوحدة الأساسية:** أصغر وحدة تخزين للصنف (مثل «كجم»). تُخزَّن كل الأرصدة بها وتُعرض بأي وحدة (مثل «3 كرتونة + 2 عبوة»).
- **قائمة الأسعار:** لكل عميل قائمة افتراضية (قطاعي / جملة / جملة الجملة / مشاريع).
- **الخصم:** على الصنف و/أو على البيان، بحد أقصى لكل دور/مستخدم؛ أي تجاوز يتحول إلى **طلب موافقة**.
- **الفترة:** كل الحركات مرتبطة بفترة محاسبية؛ تُستخدم في الترحيل الدوري.

## 2. الدخول والخروج

### 2.1 تسجيل الدخول

1. افتح رابط النظام في المتصفح.
2. في شاشة الدخول أدخل **البريد الإلكتروني** أو **رقم الهاتف** (حسب طريقة إنشاء حسابك) وكلمة المرور.
3. اضغط **تسجيل الدخول**.

> **ملاحظة:** مندوب المبيعات يدخل برقم هاتفه على تطبيق الموبايل. موظفو المكتب يدخلون بالبريد الإلكتروني على الويب.

### 2.2 تسجيل الخروج

- من أسفل الشريط الجانبي اضغط **تسجيل الخروج**.
- للحماية: لا تشارك حسابك مع آخرين؛ كل عملية تُسجَّل باسم المستخدم في **سجل التدقيق** (البند 22).

### 2.3 نسيت كلمة المرور

- تواصل مع مدير النظام لإعادة تعيين كلمة المرور (البند 25).

### 2.4 لوحة الأوامر السريعة والبحث الشامل (Command Palette — Ctrl + K)

يتضمن النظام لوحة أوامر ذكية وسريعة يمكن فتحها من أي شاشة في النظام عبر:
- الضغط على اختصار لوحة المفاتيح: `Ctrl + K` (أو `⌘K` لمستخدمي أجهزة Mac).
- أو النقر على زر **«البحث والأوامر (Ctrl + K)»** الموجود في أعلى الشريط الجانبي.

**الميزات والإمكانيات:**
1. **البحث الحي الفوري (Async Debounced Multi-Resource Search):** بمجرد كتابة حرفين، يبحث النظام لحظياً عبر الـ API في:
   - **العملاء:** باسم العميل أو كوده أو هاتفه مع إمكانية الانتقال المباشر لملف وكشف حساب العميل.
   - **الأصناف:** باسم الصنف العربي/الإنجليزي أو كود الصنف أو الباركود.
   - **بيانات الأسعار والفواتير:** برقم الفاتورة أو العميل مع حالة الاعتماد.
2. **التنقل السريع المباشر:** الوصول المباشر لكافة أقسام النظام الـ 25+ (لوحة المعلومات، نقطة البيع POS، المشتريات، الخزينة، تقارير المبيعات، إعدادات الشركة، سجل التدقيق، تشخيص النظام، إلخ).
3. **الإجراءات السريعة (Quick Actions):** أزرار وصول فوري في صدارة اللوحة لإنشاء مستند جديد (+ بيان أسعار جديد، + صنف جديد، + عميل جديد).
4. **التنقل الذكي بالأسهم:** استخدم أسهم لوحة المفاتيح (↑ و ↓) للتنقل السلس بين الأقسام والنتائج، ومفتاح `Enter` للاختيار الفوري، ومفتاح `Esc` للإغلاق السريع دون لمس الفأرة.

### 2.5 التنقل المتجاوب والقائمة الجانبية للشاشات والأجهزة الذكية (Responsive Mobile Drawer)

صُممت واجهة نظام «بيان» وفق أرقى معايير تصميم الواجهات (Modern UI/UX Design System) لتعمل بكفاءة مطلقة على أجهزة الحواسب المكتبية، والأجهزة اللوحية (Tablets)، والهواتف الذكية:
- **الشاشات الكبيرة (Desktop):** شريط جانبي ثابت (Sidebar) أنيق مقسّم موضوعياً (الرئيسية، العمليات، المخازن والمشتريات، الحسابات، الإدارة)، مع تمييز لوني واضح للصفحة الحالية وأيقونات SVG حادة وعالية الوضوح.
- **الشاشات المتوسطة والصغيرة (Mobile / Tablet):** يختفي الشريط الجانبي لتوفير أقصى مساحة عرض تشغيلية للبيانات والجداول، مع ظهور شريط علوي (Top Header Bar) يتضمن زر القائمة المتجاوبة (Hamburger Menu ☰).
- **درج التنقل الانزلاقي (Slide-over Navigation Drawer):** عند الضغط على زر القائمة في الهاتف ينسدل درج أنيق مع تأثير التمويه الضبابي الخلفي (Backdrop Blur Glassmorphism) يتيح التنقل الكامل بين كافة الشاشات مع إغلاق تلقائي عند النقر خارج القائمة.
- **شريط المسار التنفيذي (Breadcrumbs):** يعرض أعلى كل شاشة مسار التنقل الحركي (مثل: الرئيسية / المبيعات / بيان أسعار جديد) مع إشارات حالة الاتصال واسم المستخدم والدور الوظيفي.

### 3.3 قوائم الصلاحيات الكاملة (للمرجع)

- **البيانات:** `statement.create` إنشاء بيان، `statement.edit` تعديل مسودة، `statement.edit_approved` تعديل بعد الاعتماد، `statement.cancel` إلغاء، `statement.approve` اعتماد.
- **الخصومات:** `discount.line` خصم صنف، `discount.header` خصم بيان، `discount.approve` اعتماد تجاوز الحد.
- **الائتمان والتكلفة:** `credit.exception.approve` استثناء الحد الائتماني، `cost.view` رؤية التكلفة.
- **المرتجعات:** `return.create`، `return.approve`، `return.receive` استلام، `return.without_statement` مرتجع بدون بيان، `return.cash_refund` رد نقدية.
- **المخزون:** `stocktake.execute` تنفيذ الجرد، `stocktake.approve` اعتماده، `stocktake.view` عرضه، `transfer.execute`/`transfer.view` التحويلات، `opening_stock.execute` الرصيد الافتتاحي.
- **المشتريات:** `purchase_order.create`/`.approve`/`.view`، `supplier_return.create`/`.view`.
- **الخزينة:** `collection.create` تحصيل، `treasury.view`/`treasury.manage`، `cash.handover` تسليم عهدة، `daily_close.execute` الإقفال اليومي، `ledger.view` كشف حساب.
- **البيانات الأساسية:** `price.manage`، `item.manage`، `customer.manage`، `supplier.manage`، `warehouse.manage`، `customer.rating`، `label.view` الباركود ومشاركة الكشوف.
- **الإدارة:** `user.manage`/`user.view`، `report.view` التقارير، `notification.view` الإشعارات، `audit.view` التدقيق، `company.manage` إعدادات الشركة، `visit.plan.manage`/`.view`، `archive.run` الترحيل.
- **الجغرافيا والمزامنة:** `rep.track`، `geo.report`، `geo.fleet`، `sync.use`، `device.manage`.

## 4. لوحة المعلومات والتحليلات التنفيذية

تُعد **لوحة المعلومات** الشاشة الرئيسية ونبض العمليات اليومي لكافة مستويات الإدارة، حيث توفر مؤشرات لحظية (Real-Time KPIs) تُحدّث تلقائياً كل 60 ثانية أو عند النقر على زر **«تحديث البيانات 🔄»**.

### 4.1 الرسوم البيانية والتحليلات البصرية التفاعلية (SVG Visual Analytics)

تحتوي لوحة المعلومات على حزمة تحليلات مرئية متقدمة مبنية بتقنية الفيكتور الخالص (Zero-Dependency SVG) لتحقيق أعلى أداء وأوضح رؤية على كافة الشاشات:
1. **منحنى مسار المبيعات الزمني (Sales Trend Area Chart):**
   - رسم بياني مساحي ناعم بتدرج لوني أزرق يعرض تطور صافي المبيعات لآخر 7 فترات بيعية.
   - يتضمن خطاً بيانياً متدرجاً ونقاط بيانات تفاعلية.
   - عند تمرير الفأرة فوق أي نقطة، تنبثق بطاقة تفاعلية (Interactive Tooltip) باللون الداكن تعرض التاريخ بدقة، وصافي المبيعات بالجنيه المصري، وعدد فواتير البيع المصدرة.
2. **توزيع مبيعات القطاعات والتصنيفات (Category Distribution Donut Chart):**
   - رسم بياني دائري متقدم مقسّم بنسب قطاعية ملونة (حديد التسليح، دهانات وبويات، أدوات ومعدات، إكسسوارات).
   - يعرض وسيلة إيضاح لونية ذكية (Legend) توضح نسبة مساهمة كل قطاع وإجمالي إيراده.
   - يساعد مديري المشتريات والمبيعات في معرفة القطاع الأكثر نمواً وتوجيه السيولة نحو الأصناف الأعلى طلباً.
3. **شريط السيولة النقدية ورأس المال العامل (Cash Flow & Liquidity Balance Bar):**
   - شريط مقارنة بصري مزدوج بلونين مميزين (الأخضر للسيولة النقدية المتوفرة في الخزينة، والأزرق لمستحقات وديون العملاء المتداولة في السوق).
   - يوضح فورياً نسبة النقدية الجاهزة مقارنة بإجمالي رأس المال المتداول، مما يحمي المنشأة من التعثر المالي ويوجه الإدارة لتسريع وتيرة التحصيل عند تضخم ديون العملاء.
4. **لوحة صدارة العملاء والأصناف (Top Rankings & Progress Bars):**
   - **أعلى العملاء تحقيقاً للمبيعات:** قائمة تفاعلية ترتب كبار العملاء بأشرطة تقدم متدرجة ونسب مئوية من إجمالي المبيعات مع إمكانية النقر للانتقال الفوري لملف العميل.
   - **أكثر الأصناف سحباً من المخازن:** بطاقات أفقية توضح الكميات المسحوبة بالوحدات الأساسية لتجنب نفاد المخزون للأصناف الحيوية.

### 4.2 بطاقات المؤشرات اللحظية الرئيسية

- 💰 **مبيعات اليوم والشهر:** صافي الإيراد المحقق مع عدد الفواتير المعتمدة.
- 📥 **تحصيلات الخزينة:** النقدية والشيكات المحصلة اليوم لمطابقة رصيد الخزينة.
- ⚠️ **أصناف تحت حد الطلب:** تنبيه فوري بالأصناف التي انخفض رصيدها عن الحد الأدنى لمخزون الأمان مع رابط مباشر لطلب شراء.
- ⏳ **طلبات بانتظار الموافقة:** عداد بالطلبات المعلقة للخصومات أو الحدود الائتمانية للبت فيها فوراً.

## 5. البيانات الأساسية

### 5.1 الأصناف

**الغرض:** تعريف كل منتج ببياناته ووحداته وأسعاره وصوره.

**خطوات إنشاء صنف:**

1. من الشريط الجانبي اختر **الأصناف** ← **+ صنف جديد**.
2. أدخل: الكود، الباركود (اختياري)، الاسم عربي/إنجليزي، التصنيف (حديد/بويّات/أدوات/إكسسوارات)، الماركة، المنشأ.
3. للحالة: نشط / موقوف، والحد الأدنى للمخزون (نقطة إعادة الطلب).
4. **خصائص حسب التصنيف:**
   - **حديد:** القطر، الطول، الدرجة، الوزن النظري للقطعة.
   - **بويّات:** اللون/كود اللون، السعة، النوع، وتتبع التشغيلة والصلاحية (اختياري).
5. أضف **الوحدات المتعددة** (البند 6.1) و**الصور**.
6. اضغط **حفظ**.

**الأصناف المتغيرة (Variants):** عرّف صنفاً أساسياً بتنويعات (مثل دهان بعدة ألوان وعبوات) دون تكرار البيانات.

**الباركود/QR:** من صفحة الصنف يمكنك طباعة **ملصق باركود/QR** (يحتاج صلاحية `label.view`).

### 5.2 قوائم الأسعار ووحدة التخزين

**خطوات ضبط وحدات الصنف:**

1. افتح الصنف ← تبويب **الوحدات**.
2. حدّد **الوحدة الأساسية** (أصغر وحدة تخزين).
3. أضف وحدات بديلة مع **معامل التحويل** للوحدة الأساسية، وهل هي وحدة **بيع/شراء/كلاهما**، وسعر بيع مستقل وباركود (اختياري).
4. **نوع القياس:** عددي (أعداد صحيحة فقط) أو وزني (كسور بدقة 3 خانات).
5. مثال: حديد 12مم — الأساسية «كجم»، و«سيخ = 10.656 كجم»، و«طن = 1000 كجم».

**تسعير يومي للحديد:**

1. من **الأسعار** اختر شاشة **التحديث الجماعي**.
2. اختر أصناف الحديد، وطبّق التغيير **بنسبة % أو بقيمة** أو بإدخال جماعي.
3. احفظ؛ يُسجَّل كل تغيير (من غيّر، متى، من كم إلى كم) في **سجل تغيرات الأسعار**.

**تنبيه:** عند البيع بأقل من التكلفة أو أقل من الحد الأدنى للسعر يظهر تنبيه ويتطلب صلاحية استثناء.

### 5.3 العملاء

**الغرض:** بيانات العميل، حدّه الائتماني، قائمة أسعاره، ومندوبه.

**خطوات إنشاء عميل:**

1. **العملاء** ← **+ عميل جديد**.
2. أدخل: الاسم، النشاط، العنوان، الموقع على الخريطة (اختياري)، الهاتف، الرقم الضريبي، **المندوب المسؤول**، **قائمة السعر الافتراضية**.
3. أدخل **الحد الائتماني** و**مدة السداد**.
4. احفظ.

**تصنيف العملاء وتقييم السداد:** صنّف العميل (A/B/C) مع تقييم سداد (يحتاج `customer.rating`).

**تحويل عميل بين مناديب:** عيّن العميل لمندوب أو أكثر مع تسجيل **تاريخ التحويل**.

**كشف حساب العميل:** يعرض البيانات والمرتجعات والتحصيلات والرصيد الافتتاحي.

### 5.4 الموردين

- البيانات: الاسم، النشاط، بيانات الاتصال، الرقم الضريبي.
- كشف حساب المورد، السداد، ومرتجع مشتريات (البند 10).

### 5.5 التصنيفات والماركات والمخازن والفروع

- **التصنيفات:** حديد/بويّات/أدوات/إكسسوارات (تُدار من شاشة التصنيفات).
- **الماركات:** تُدار من شاشة الماركات.
- **المخازن:** البند 6.
- **الفروع:** تُدار من شاشة الفروع.

## 6. المخازن والأرصدة

### 6.1 إدارة المخازن

1. **المخازن** ← **+ مخزن جديد**.
2. حدّد: الاسم، النوع (رئيسي / حديد / بويّات / سيارات المناديب / معرض / تالف)، والمسؤول.
3. احفظ.

**المخزون يُخزَّن دائماً بالوحدة الأساسية** ويُعرض بأي وحدة.

### 6.2 حركات المخزون

الحركات المتاحة: استلام، صرف (بيع)، تحويل بين مخازن، تسوية جرد، مرتجع، ورصيد افتتاحي.

### 6.3 بطاقة الصنف (Item Ledger)

- لعرض كل حركات صنف في مخزن: الكمية الداخلة/الخارجة والرصيد بعد كل حركة.
- متاحة أيضاً كتقرير في **التقارير** ← **بطاقة الصنف** (البند 18).

### 6.4 أرصدة لحظية

- من **المخازن** يعرض النظام رصيد كل صنف في كل مخزن لحظياً، مع حجز مؤقت للكميات في البيانات المسودة (اختياري).

## 7. بيان الأسعار

> **مهم: هذه هي الفاتورة.** المراحل: **مسودة ← معتمد ← (مرحّل)**، وحالة جانبية **ملغي**.

### 7.1 إنشاء بيان أسعار (السيناريو الأساسي لنقطة البيع)

1. الشريط الجانبي ← **بيانات الأسعار** (أو **بيان أسعار جديد**) ← **+ بيان أسعار جديد**.
2. **رأس البيان:**
   - **العميل** (يحدد تلقائياً قائمة سعره والمندوب المسؤول).
   - **المخزن**، **تاريخ البيان**، **شروط الدفع** (نقدي/آجل/مختلط).
   - **نوع خصم البيان** (نسبة % أو قيمة ثابتة)، و**قيمة/نسبة الخصم**.
   - **الشحن (ج)**، **المدفوع نقداً (ج)**، **الضريبة %** (إن كانت مفعّلة).
3. **البنود:** اضغط **+ إضافة بند** ثم لكل بند:
   - **الصنف** ← **الوحدة** ← **الكمية** ← **السعر** (يُجلب من قائمة سعر العميل) ← **الخصم** (نسبة أو قيمة).
   - للحديد: أدخل **الوزن الفعلي كجم** و**ملاحظة الوزن الفعلي** عند اختلاف الوزن الفعلي (وزن الشاحنة) عن النظري.
4. **التذييل (يُحسب آلياً):** الإجمالي الفرعي، خصم البيان، النقل، الضريبة، الصافي، المدفوع، المتبقي.
5. اضغط **حفظ كمسودة** أو **اعتماد**.

> **تحويل الخصم آلياً:** إدخال النسبة يُظهر القيمة والعكس، أثناء الإدخال.
> **ترتيب الخصومات:** خصم الصنف أولاً ثم خصم البيان.

### 7.2 الخصومات وحدودها

- لكل دور ومستخدم **حد أقصى** للخصم على الصنف وحد أقصى على البيان.
- إن تجاوز الخصم حدّك: يتحول إلى **طلب موافقة** يصل للمشرف/المالك (البند 17).
- يُحفظ سجل بكل تعديل على الخصم في سجل التدقيق.

### 7.3 قواعد التحقق

- **الكمية أكبر من المتاح:** يُمنع (أو يُسمح بالرصيد السالب حسب الإعداد).
- **تجاور الحد الائتماني:** تنبيه أو منع أو طلب استثناء (`credit.exception.approve`).
- **البيع بأقل من التكلفة:** يحتاج صلاحية استثناء.

### 7.4 تعديل بيان بعد الاعتماد

- لا يُحذف البيان المعتمد، بل يُنشأ **نسخة معدلة** مع حفظ سجل التعديلات (يحتاج `statement.edit_approved`).

### 7.5 إلغاء بيان

1. من صف البيان اضغط **إلغاء**.
2. أدخل **سبب الإلغاء (إلزامي)**.
3. أكّد. يحتاج صلاحية `statement.cancel`.

### 7.6 الطباعة والمشاركة

- **الطباعة:** A4 أو إيصال حراري 80مم (من صفحة الطباعة `/statements/[id]/print`).
- يظهر على المطبوع عنوان **«بيان أسعار»** مع شعار الشركة وبياناتها ورصيد العميل قبل وبعد.
- **مشاركة PDF عبر واتساب** (من الموبايل أو الويب).

### 7.7 عرض تفاصيل بيان

- من صف البيان اضغط **عرض** لرؤية الرأس والبنود والإجماليات وبيانات الشحن والوزن الفعلي.

### 7.8 شاشة كاشير المعرض ونقطة البيع السريعة (POS — Point of Sale)

شاشة مخصصة لمعارض ومنافذ البيع المباشر ومحلات التجزئة النقدية التي تتطلب سرعة فائقة في تسجيل البنود وتفريغ طوابير العملاء دون أي بطء (`/pos`).

**المكونات الأساسية لشاشة الكاشير:**
1. **شريط البحث والباركود الذكي:** خانة إدخال بارزة ومحاطة بهالة زرقاء تستقبل إدخال ماسح الباركود الليزري أو اليدوي تلقائياً، مع دعم البحث الفوري بالاسم أو كود الصنف.
2. **شريط التصنيفات السريع (Quick Categories):** أزرار تصفية لمسية ملونة أعلى الشاشة (الكل، حديد وبناء، بويات ودهانات، أدوات ومعدات، إكسسوارات) لعرض الأصناف الشائعة بنقرة واحدة.
3. **كتالوج الأصناف البصري (Product Grid):** بطاقات تفاعلية تعرض صورة الصنف، كوده، سعره بالوحدة الافتراضية، ورصيده اللحظي بالمخزن لتنبيه الكاشير قبل نفاد الكمية.
4. **سلة المبيعات النشطة (Active Cart):** لوحة جانبية كاملة تعرض بنود الفاتورة الحالية مع إمكانية تعديل الكميات بأزرار (+ / -)، اختيار وحدة القياس (كرتونة / عبوة / كجم)، وإدخال نسبة أو قيمة خصم على البند.
5. **حاسبة النقدية السريعة (Tender Calculator):** أزرار جاهزة للفئات النقدية الشائعة بالجنيه المصري: **[المبلغ بالضبط]**، **[+20]**، **[+50]**، **[+100]**، **[+200]** لحساب المبلغ المستلم فورياً دون الحاجة لكتابة الأرقام يدوياً.
6. **مؤشر الباقي للعميل (Change Due):** مربع بارز بخلفية خضراء زمردية وخط عريض يوضح المبلغ الواجب رده للعميل فورياً لمنع أخطاء الصرافة وتسريع دورة الحساب.
7. **طرق السداد المتنوعة (Payment Methods):**
   - 💵 **نقد / كاش:** السداد الفوري وتحديث رصيد خزينة المعرض.
   - 📱 **محفظة إلكترونية / إنستاباي (InstaPay & Vodafone Cash):** لتسجيل مبيعات التحويلات الفورية مع حقل لرقم العملية.
   - 💳 **بطاقة بنكية / فيزا:** لنقاط البيع الإلكترونية (POS Terminals).
   - 📋 **آجل / على الحساب:** لعملاء المعرض المعتمدين والمقيدين بالنظام.
8. **تعليق واسترجاع الفواتير (Hold & Resume Tickets):**
   - عند وقوف عميل لتفقد منتج إضافي، يضغط الكاشير على **«⏸️ تعليق الفاتورة»** لحفظ السلة مؤقتاً بالذاكرة والانتقال لخدمة العميل التالي.
   - يظهر عداد الفواتير المعلقة في شريط الأدوات العلوي، وبنقرة واحدة على **«استرجاع الفواتير المعلقة»** تظهر قائمة بالسلل المعلقة مع توقيت تعليقها وإجماليها للعودة إليها ومتابعة المحاسبة.
9. **معاينة وطباعة الإيصال الحراري 80mm (Thermal Receipt):**
   - عند النقر على **«إتمام البيع (F4)»**، يُسجل البيان معتمداً ويُخصم المخزون لحظياً، وتنبثق نافذة معاينة إيصال 80 مم أنيق يتضمن اسم وشعار الشركة، رقم الفاتورة والباركود، تفاصيل البنود والكميات، الضرائب والخصومات، ورمز الاستجابة السريع QR.
   - تتصل النافذة فورياً بأمر الطباعة `window.print()` وتدعم أمر فتح درج النقدية التلقائي (Cash Drawer Kick).

**اختصارات لوحة المفاتيح المعتمدة للكاشير:**
- `F2`: التركيز الفوري لمؤشر الكتابة في خانة مسح الباركود.
- `F4`: إتمام عملية البيع وفتح نافذة الحساب والطباعة.
- `F8`: تفريغ السلة الحالية والبدء في فاتورة جديدة فوراً.
- `Esc`: إغلاق النوافذ المنبثقة ومعاينة الطباعة.

> **نغمة التأكيد الصوتية (Audio Beep):** يستخدم النظام تقنية الصوت التخليقي (Web Audio Synthesis) لإصدار رنة صوتية واضحة (Chime) تؤكد للكاشير نجاح قراءة الباركود وإضافة الصنف دون الحاجة للنظر المستمر في شاشة الحاسوب.

## 8. المرتجعات

### 8.1 أنواع المرتجع

1. **حسب العميل:** اختر العميل ← تظهر بياناته السابقة ← حدّد البيان والبند.
2. **حسب المندوب:** اختر المندوب ← يظهر ما باعه ← اختر العميل ثم البيان ثم البند.

### 8.2 القاعدة الجوهرية

- المرتجع **مرتبط ببيان البيع الأصلي** ويُقيَّم بقيمته فيه: سعر الوحدة **بعد خصم الصنف ونصيبه من خصم البيان** كما في البيان الأصلي (لا بسعر اليوم).
- الكمية المرتجعة **لا تتجاوز** (الكمية المباعة − ما سبق إرجاعه).
- يمكن إرجاع جزء، وبوحدة مختلفة مع التحويل.
- لا يمكن إرجاع صنف لم يُبع للعميل إلا بصلاحية **«مرتجع بدون بيان»** (`return.without_statement`) مع موافقة.

### 8.3 خطوات إنشاء مرتجع

1. **المرتجعات** ← **+ مرتجع جديد**.
2. اختر طريقة البحث (عميل أو مندوب) ثم البيان الأصلي.
3. حدّد البنود والكميات المرتجعة.
4. أدخل **سبب المرتجع (إلزامي):** عيب / خطأ طلب / تلف / أخرى.
5. حدّد **حالة البضاعة:** **صالحة** (تعود للمخزون) أو **تالفة** (مخزن التالف/تسوية).
6. حدّد **الأثر المالي:** خصم من رصيد العميل / رد نقدية (`return.cash_refund`) / رصيد دائن.
7. احفظ. قد يحتاج **اعتماد** المشرف/المحاسب قبل التأثير النهائي (حسب الإعداد).

### 8.4 استلام المرتجع (المخزن)

- أمين المخزن يستخدم **استلام مرتجع** (`return.receive`) لإدخال البضاعة الصالحة للمخزون.

## 9. التحصيل والخزينة

### 9.1 سند قبض (تحصيل)

1. **التحصيلات** ← **+ سند قبض**.
2. اختر العميل، وحدّد إن كان التحصيل **مرتبطاً ببيان محدد** أو **على الحساب**.
3. اختر **طريقة الدفع:** نقدي / تحويل / شيك / فودافون كاش / إنستاباي.
4. أدخل المبلغ والتاريخ، واحفظ. يحتاج صلاحية `collection.create`.

### 9.2 سندات الصرف

- متاحة من نفس شاشة الخزينة لصرف النقدية مع تسجيل السبب.

### 9.3 حافظة الشيكات

- متابعة حالة كل شيك: **تحت التحصيل / محصّل / مرتد**.

### 9.4 تسليم عهدة المندوب

1. المندوب (أو المشرف) ينشئ **محضر تسليم عهدة** (`cash.handover`).
2. يُحضّر المبلغ المحصَّل ويُسلَّم للخزينة مع **مطابقة** التحصيلات المسلَّمة.

### 9.5 الإقفال اليومي

1. من **الخزينة** ← **الإقفال اليومي** (`daily_close.execute`).
2. راجع الحركات، أكّد الإقفال، واطبع تقرير الإقفال.

### 9.6 كشف حساب (Ledger)

- **كشف الحساب** يعرض كل حركات العميل/المورد: بيانات، مرتجعات، تحصيلات، ورصيد.

---

## 10. الموردين والمشتريات

### 10.1 بيان توريد (شراء)

- بنفس منظومة الوحدات والخصومات كبيان الأسعار، لكن موجّه للمورد.
- عند **اعتماد** بيان التوريد يُحدَّث **آخر سعر شراء** تلقائياً (مع خيار التعطيل).
- **مصاريف النقل والمصاريف الإضافية** تُوزّع على تكلفة الأصناف (Landed Cost) — اختياري.

### 10.2 أوامر الشراء (Purchase Orders)

1. **أوامر الشراء** ← **+ أمر شراء** (`purchase_order.create`).
2. أضف البنود والكميات المتوقعة، واعتمده (`purchase_order.approve`).
3. عند الاستلام يُنشأ بيان توريد مرتبط.

### 10.3 مرتجع المشتريات

- **مرتجعات المشتريات** ← **+ مرتجع** (`supplier_return.create`)، مرتبط ببيان التوريد الأصلي.

### 10.4 كشف حساب المورد

- يعرض التوريدات والسدادات والمرتجعات والرصيد.

---

## 11. عروض الأسعار

**الغرض:** إصدار عرض سعر للعميل قبل البيع.

1. **عروض الأسعار** ← **+ عرض سعر جديد**.
2. أدخل العميل والبنود والأسعار والخصومات (مثل بيان الأسعار لكن دون تأثير مخزني).
3. للطباعة: من صفحة العرض، **طباعة** (A4/A5/80مم) أو تنزيل PDF عربي.
4. **التحويل إلى بيان أسعار:** اضغط **تحويل إلى بيان** — يُنشأ بيان أسعار من العرض بضغطة واحدة.

## 12. الجرد

### 12.1 دورة الجرد (لكل مخزن على حدة)

1. **فتح جلسة جرد** لمخزن (كلي أو جزئي: تصنيف/ماركة/مجموعة أصناف) — صلاحية `stocktake.execute`.
2. **تجميد رصيد النظام** لحظة الفتح (Snapshot) مع منع/تحذير الحركات حسب الإعداد.
3. **إدخال الكميات الفعلية** من الويب أو الموبايل (بالمسح أو يدوياً)، ويدعم أكثر من عداد.
4. **المقارنة:** عرض الفروقات بالكمية **والقيمة** (عجز / زيادة).
5. **مراجعة وإعادة عد** للأصناف ذات الفروقات الكبيرة.
6. **اعتماد المالك** (`stocktake.approve`) ← إنشاء **حركة تسوية تلقائية** ← إغلاق الجلسة وحفظ تقرير الجرد.

### 12.2 تقييم المخزون

- **القيمة = الكمية × آخر سعر شراء للصنف** (الطريقة المعتمدة).
- لكل مخزن على حدة، ولإجمالي كل المخازن.
- خيارات العرض: بالوحدة الأساسية / بالوحدات الكبرى.
- **أصناف «بدون سعر»:** تُعرض في تنبيه ويُستبعد من الإجمالي مع بيان عددها.

### 12.3 طباعة الجرد

- من صفحة الجلسة: `/stocktakes/[id]/print` لطباعة ورقة الجرد والفروقات.

---

## 13. التحويلات والرصيد الافتتاحي

### 13.1 التحويل المخزني

1. **التحويلات** ← **+ تحويل جديد** (`transfer.execute`).
2. اختر المخزن المصدر والهدف، وأضف الأصناف والكميات.
3. اعتمد التحويل؛ يُخصم من المصدر ويُضاف للهدف.
4. للطباعة: `/transfers/[id]/print`.

### 13.2 الرصيد الافتتاحي

- **الرصيد الافتتاحي** (`opening_stock.execute`) لإدخال الأرصدة الأولية عند بدء التشغيل لكل صنف/مخزن.

## 14. العروض والأسعار الخاصة

## 16. الزيارات والتتبع

### 16.1 خطة الزيارات

### 16.2 التتبع الجغرافي

- **يعمل فقط** عند تشغيل التطبيق وتسجيل **بدء الوردية** / **إنهاء الوردية**.
- يرسل الموقع كل 30–120 ثانية (قابل للضبط) مع توفير البطارية.
- **الخريطة المباشرة** (`/geo`) للمشرف/الإدارة تعرض آخر موقع لكل مندوب (يحتاج `rep.track`/`geo.fleet`).
- **مسار اليوم (Route Replay):** إعادة عرض خط سير المندوب والتوقفات.
- ربط الموقع بكل بيان/زيارة/تحصيل، مع تنبيه عند تجاوز نطاق القرب (مثل 150م) من موقع العميل.

> **الخصوصية:** إعلام المندوب بالتتبع وأخذ موافقة موقعة، لا تتبع خارج ساعات الوردية، وإشعار دائم أثناء التتبع على أندرويد، والاحتفاظ بسجلات الموقع مدة محددة ثم حذفها تلقائياً.

## 20. الترحيل والأرشفة

> **الغرض:** تخفيف قاعدة البيانات التشغيلية بترحيل البيانات المنتهية لملفات خارجية وبدء فترة نظيفة. يحتاج صلاحية `archive.run`.

### 20.1 خطوات الترحيل الدوري

1. **الأرشيف والترحيل** ← **إغلاق فترة / ترحيل**، وحدّد المدى (من–إلى أو حتى تاريخ).
2. **فحوصات ما قبل الترحيل:** لا مسودات، لا بيانات غير متزامنة، لا مرتجعات معلقة، ثم **نسخة احتياطية كاملة تلقائياً**.
3. **التصدير:** تُنشأ حزمة أرشيف تحتوي ملفات Excel لكل نوع، PDF مجمّع للبيانات (اختياري)، ملف JSON/SQLite كامل، وملف `manifest` فيه الأعداد والإجماليات و**Checksum SHA-256** لكل ملف.
4. **التحقق:** مطابقة الإجماليات والأعداد بين الحزمة وقاعدة البيانات.
5. **الحفظ:** نزّل الحزمة واحفظها، مع تأكيد أنك حفظتها.
6. **الحذف من القاعدة التشغيلية** بعد تأكيد صريح (بكتابة كلمة تأكيد).
7. **تدوير الأرصدة:** إنشاء أرصدة افتتاحية للفترة الجديدة (عملاء، موردون، أصناف بكل مخزن، خزائن).
8. بدء ترقيم جديد للبيانات (اختياري) مع حفظ البادئة/السنة (مثل `BP-2027-000001`).

### 20.2 عارض الأرشيف

- افتح حزمة قديمة للاطلاع والبحث والطباعة دون إدخالها لقاعدة البيانات.
- كشف حساب العميل يعرض رصيداً افتتاحياً «مرحّلاً» مع رابط الأرشيف.
- **الاستعادة:** للمدير فقط وبحالات محدودة.
- جدولة تذكير دوري: «مضى X شهر منذ آخر ترحيل»، وسجل بكل عمليات الترحيل.

## 21. النسخ الاحتياطي

1. **النسخ الاحتياطي** — يعرض النسخ (اليومية المجدولة افتراضياً 02:00، ويدوياً).
2. **نسخة جديدة:** اضغط **إنشاء نسخة** لبدء نسخة فورية.
3. **تحقق:** زر **تحقق** (Checksum وفك التشفير) للاطمئنان على سلامة النسخة.
4. **تمرين استرجاع:** زر **استرجاع تجريبي** ينشئ قاعدة مؤقتة، يسترجع النسخة، يتحقق من الأعداد، ثم يحذف القاعدة المؤقتة — للتأكد الدوري أن النسخ قابلة للاسترجاع فعلاً.

> النسخ مشفّرة بمفتاح `BACKUP_ENCRYPTION_KEY`. احفظ نسخة منها **خارج الخادم** دورياً.

## 23. الأدوات المساعدة

- **أدوات مساعدة** ← تبويب **حاسبة كميات الدهانات:** المساحة + عدد الوجوه + تغطية اللتر + حجم العبوة ← اللترات المطلوبة و**عدد العبوات** وإجمالي المشترى.
- تبويب **حاسبة أوزان الحديد:** القطر (مم) + الطول (م) + عدد الأسياخ ← وزن المتر الطولي، وزن السيخ الواحد، والوزن الإجمالي.
- الحاسبات متاحة أيضاً داخل تطبيق المندوب.

## 24. إعدادات الشركة وتشخيص النظام

> يحتاج الدخول صلاحية `company.manage`.

### 24.1 الملف التعريفي والضريبة والسلوكيات العامة

- **بيانات وهوية الشركة:** اسم المنشأة بالعربية، رقم الهاتف الرسمي، البريد الإلكتروني، واسم جهة الاتصال — تُطبع هذه البيانات ورقم التسجيل الضريبي تلقائياً في ترويسات الفواتير وعروض الأسعار والإيصالات.
- **شعار الشركة (Logo):** رفع شعار المنشأة بصيغ الصور (PNG / JPEG / WebP) ليظهر على مطبوعات الفواتير وكشوف الحسابات.
- **نسبة الضريبة الافتراضية (%):** تحديد نسبة الضريبة (مثل 14% ضريبة القيمة المضافة) لتُطبق افتراضياً على بيانات الأسعار والمشتريات ما لم تُعدّل يدوياً.
- **الميزات والخصائص المفعّلة (Feature Flags):** تفعيل أو تعطيل ميزات المنظومة على مستوى الشركة (مثل: التتبع الجغرافي للأسطول `geotracking.fleet`، التسعير الجماعي للحديد `pricing.bulk`، تقييم المخزون `reports.valuation`، الأرشفة الدورية `archiving.core`).

### 24.2 شاشة تشخيص وسلامة النظام والمكونات الحيوية (System Diagnostics & Health)

شاشة رقابية وتشخيصية حية (`/settings/diagnostics`) مخصصة للإدارة العليا والمشرفين لمراقبة الجاهزية التشغيلية والاطمئنان على سلامة قواعد البيانات والخدمات:
1. **شريط الحالة والجاهزية العام (System Health Status):**
   - مؤشر استقرار بصري عريض (باللون الأخضر الزمردي عند استقرار كافة الخدمات، أو الأصفر عند وجود تنبيه تدهور طفيف، أو الأحمر عند انقطاع أي خدمة).
2. **محرك قاعدة البيانات وزمن الاستجابة (PostgreSQL Latency):**
   - قياس حي بالمللي ثانية لسرعة استجابة قاعدة البيانات (زمن الوصول الفعلي Query Ping Latency).
   - المعيار التشغيلي: أقل من 10ms يعتبر استجابة فائقة السرعة؛ من 10ms إلى 50ms أداء طبيعي ومستقر؛ أعلى من 100ms يتطلب مراجعة الشبكة أو ضغط الاستعلامات.
3. **سلامة الترحيلات الهيكلية (Database Schema Migrations):**
   - فحص آلي ومطابقة كاملة لـ 46 ترحيلاً من ترحيلات Prisma بدون أي ترحيل معلق (`0 pending migrations`) للتأكد من تطابق الجداول والحقول مع كود الخادم.
   - التحقق من تفعيل آلية عزل المستأجرين وأمان البيانات (Row-Level Security RLS).
4. **خدمة التخزين السحابي للملفات (Object Storage Health):**
   - فحص اتصال مشغل التخزين (S3 / MinIO أو نظام التخزين المحلي Local Storage).
   - التحقق من وجود وجاهزية حاوية التخزين السحابي (Bucket Verification) لتخزين وحفظ صور الأصناف وملفات حزم الأرشيف والنسخ الاحتياطية.
5. **منظومة النسخ الاحتياطي المشفر وتمرين الاسترجاع التجريبي (Restore Drill):**
   - استعراض موعد الجدولة اليومية الآلية المشفرة بخوارزمية AES-256-GCM (يومياً الساعة 02:00 فجراً).
   - عرض إجمالي النسخ المحفوظة وحجمها وحالة آخر تمرين استرجاع دوري.
   - **زر اختبار الاسترجاع الفوري (بدء تمرين استرجاع تجريبي):** يقوم الخادم فور النقر بإنشاء قاعدة بيانات فرعية معزولة، وفك تشفير أحدث نسخة احتياطية واسترجاع كافة الجداول، والتحقق من سلامة الأعداد والقيود، ثم حذف القاعدة المؤقتة وتنظيفها دون أي مساس بالقاعدة التشغيلية الحية، ويصدر تقريراً فورياً بنجاح الاختبار.
6. **مجدول التنبيهات والأجهزة المتصلة:**
   - فحص عمل مجدول التنبيهات الدورية كل ساعة لمراقبة تجاوز الحدود الائتمانية والأصناف تحت حد إعادة الطلب.
   - إحصاء عدد أجهزة هواتف المناديب النشطة والمسجلة على المنظومة.
7. **موارد الخادم والبيئة التشغيلية (Server Runtime & Performance):**
   - استعراض إصدار بيئة التشغيل Node.js، نظام التشغيل (Linux / Windows)، مدة التشغيل المستمر دون انقطاع (Server Uptime بالأيام والساعات)، وحجم الذاكرة العشوائية المستهلكة (Heap & RSS RAM).

## 26. السيناريوهات الكاملة

### السيناريو 1: يوم بيع كامل على الويب (موظف مبيعات)

1. سجّل الدخول، وافتح **لوحة المعلومات** للاطلاع السريع.
2. **بيانات الأسعار** ← **+ بيان أسعار جديد** ← اختر العميل (تظهر قائمته ومندوبه).
3. أضف البنود (صنف/وحدة/كمية/سعر/خصم).
4. أدخل خصم البيان إن لزم؛ لو تجاوز حدّك سيُطلب اعتماد.
5. **حفظ كمسودة** ثم مراجعة، أو **اعتماد** مباشرة.
6. **طباعة** A4 أو إيصال 80مم، أو **مشاركة PDF** عبر واتساب.
7. إذا رغب العميل بإرجاع صنف: انتقل للبند 8.

### السيناريو 2: تحصيل من عميل (محاسب)

1. **التحصيلات** ← **+ سند قبض**.
2. اختر العميل، اربطه ببيان أو على الحساب، اختر طريقة الدفع وأدخل المبلغ.
3. احفظ؛ يتحدّث رصيد العميل فوراً.
4. في نهاية اليوم: **الخزينة** ← **الإقفال اليومي** واطبع التقرير.

### السيناريو 3: مرتجع بضاعة معتمدة (موظف/مندوب)

1. **المرتجعات** ← **+ مرتجع** ← ابحث **بالعميل** أو **بالمندوب**.
2. اختر البيان الأصلي، حدّد البنود والكميات.
3. أدخل **السبب** الإلزامي، وحدّد **حالة البضاعة** (صالحة/تالفة).
4. حدّد **الأثر المالي** (خصم رصيد / رد نقدية).
5. إن لزم اعتماد، سيصل الطلب للمشرف؛ بعد الاعتماد يذهب للمخزن للاستلام.

### السيناريو 4: جرد مخزن (أمين مخزن + مالك)

1. أمين المخزن: **المخازن** ← **جلسة جرد جديدة** لمخزن محدد.
2. إدخال الكميات الفعلية (ويب/موبايل، ويدعم أكثر من عداد).
3. مراجعة الفروقات بالكمية والقيمة، وإعادة العد للفروقات الكبيرة.
4. المالك: **اعتماد الجرد** ← حركة تسوية تلقائية وإغلاق الجلسة.
5. اطبع تقرير الفروقات من **التقارير** ← **فروقات الجرد**.

### السيناريو 5: حديد — بيع بالوزن الفعلي

1. أنشئ بياناً بصنف حديد، والوحدة «سيخ» أو «طن».
2. أدخل **الوزن الفعلي كجم** وملاحظة، عند اختلاف وزن الشحنة عن النظري.
3. راجع تقرير **ملاحظات الوزن الفعلي** لاحقاً لمتابعة الفروقات.

### السيناريو 6: عرض سعر يتحول لفاتورة

1. **عروض الأسعار** ← **+ عرض جديد** بأصناف العميل وأسعارها.
2. اطبعه للعميل PDF/A4.
3. عند الموافقة: **تحويل إلى بيان** ← يُنشأ بيان أسعار جاهز.

### السيناريو 7: ترحيل فترة (مالك/مدير)

1. **الأرشيف والترحيل** ← حدّد المدى.
2. تجاوز الفحوصات (لا مسودات/معلّقات)، تُؤخذ نسخة احتياطية تلقائياً.
3. تُصدّر الحزمة وتُتحقق، ثم نزّلها واحفظها وأكّد الحفظ.
4. أكّد الحذف من القاعدة التشغيلية، وتبدأ أرصدة افتتاحية وترقيم جديد للفترة.

### السيناريو 8: يوم مندوب كامل (تطبيق الموبايل)

1. سجّل الدخول وابدأ **الوردية**، وزامن الأصناف والعملاء والأسعار.
2. اتّبع **خطة الزيارات**، وسجّل كل زيارة (تمت/لم تتم + سبب).
3. عند العميل: أنشئ **بيان أسعار** (أو مرتجع/تحصيل) — يعمل **دون إنترنت** ويُحفظ محلياً.
4. عند توفر الاتصال يُرفع تلقائياً مع إعادة المحاولة. إن تغيّر سعر/رصيد أثناء الأوفلاين يظهر البيان **«بانتظار المراجعة»**.
5. أنهِ الوردية و**سلّم العهدة النقدية** للخزينة.

### السيناريو 9: متابعة مندوب (مشرف)

1. **الخريطة المباشرة** تعرض آخر موقع لكل مندوب (خلال ورديته).
2. **مسار اليوم** لإعادة عرض خط السير والتوقفات.
3. **تقرير أداء المناديب** و**التارجت والعمولات** لمتابعة الأرقام.
4. أي طلب خصم متجاوز يصل عبر **الموافقات** للبتّ فيه.

### السيناريو 10: افتتاح شركة جديدة (مدير النظام)

1. **إعدادات الشركة:** البيانات والضريبة.
2. **المخازن** بدءاً بالمخزن الرئيسي.
3. **الوحدات والأصناف** ثم **الأسعار** (تسعير يومي للحديد).
4. **العملاء** و**الموردين** و**قوائم الأسعار** والمندوبين.
5. **الرصيد الافتتاحي** للأصناف في كل مخزن، وأرصدة العملاء/الموردين.
6. **المستخدمون والأدوار** بحدود خصم مناسبة.

### السيناريو 11: البيع السريع في معرض البيع المباشر (كاشير نقطة البيع POS)

1. افتح شاشة **نقطة البيع** (`/pos`) من القائمة أو عبر اختصار `Ctrl + K` واكتب `POS`.
2. تأكد من وقوف مؤشر البحث في خانة الباركود (اضغط `F2` إن لزم).
3. مرّر قارئ الباركود على أصناف العميل (يُضاف الصنف تلقائياً مع نغمة صوتية مألوفة).
4. للأصناف التي لا تحمل باركوداً: اضغط على التصنيف (بويات، حديد، لوازم) ثم انقر على بطاقة الصنف أو ابحث باسمه.
5. عدّل الكميات والوحدات من لوحة السلة.
6. إذا طلب العميل وقتاً لإحضار بضاعة إضافية: اضغط **«⏸️ تعليق الفاتورة»** لخدمة العميل الذي يليه فوراً دون تأخير.
7. عند المحاسبة: انقر زر الفئة النقدية المستلمة (مثل `+100` أو `+200` أو `المبلغ بالضبط`) ليظهر الباقي الواجب رده للعميل في مربع أخضر فوري.
8. اضغط `F4` لإتمام البيع ← تُسجل الفاتورة وتُطبع قسيمة الشراء 80 مم على الطابعة الحرارية وتُسلّم للعميل.

## 27. أسئلة ومشكلات شائعة

| المشكلة | الحل |
| --- | --- |
| لا أرى زراً/شاشة أتوقعها | دورك لا يملك الصلاحية — راجع مدير النظام (البند 3) |
| خصمي مرفوض | تجاوز حدّك؛ سيصل طلب موافقة، أو اطلب من المالك الاعتماد |
| لا يمكن البيع بهذه الكمية | الكمية أكبر من المتاح (أو الرصيد السالب معطّل) |
| منعني النظام من البيع | تجاوز الحد الائتماني للعميل — يلزم تسوية أو استثناء معتمد |
| كيف أفتح شاشة الكاشير السريعة؟ | اضغط `Ctrl + K` واكتب `POS` أو اختر «نقطة البيع» من الشريط الجانبي |
| كيف أعلق فاتورة عميل في المعرض؟ | اضغط زر «⏸️ تعليق الفاتورة» في شاشة POS؛ تُحفظ بالذاكرة ويمكن استرجاعها بنقرة واحدة |
| قارئ الباركود لا يُصدر صوتاً في الكاشير | تأكد من تفعيل صوت المتصفح؛ يصدر النظام رنة إلكترونية Web Audio تؤكد قراءة الكود |
| مرتجع مرفوض | صنف لم يُبع لهذا العميل — يلزم «مرتجع بدون بيان» مع موافقة |
| الأسعار غير محدّثة | راجع تسعير الحديد الجماعي وسجل تغيرات الأسعار |
| بيانات المندوب لم تظهر | لم تُرفع/تُزامن؛ راجع **الإشعارات** ← حالة المزامنة، أو حالتها «بانتظار المراجعة» |
| نسخة احتياطية فاشلة | تحقق من `BACKUP_ENCRYPTION_KEY` والمكان؛ نفّذ «تمرين استرجاع» للتأكد |
| ما هو تمرين الاسترجاع التجريبي (Restore Drill)؟ | فحص دوري آمن يسترجع أحدث نسخة احتياطية في قاعدة مؤقتة ويتحقق من سلامتها ثم يحذفها |
| ماذا يعني رقم الكمون (Latency) في تشخيص النظام؟ | زمن استجابة قاعدة البيانات بالمللي ثانية؛ القيم أقل من 50ms تدل على استقرار وسرعة ممتازة |
| لا تصل إشعارات للأجهزة | لم تُفعّل اعتمادات FCM بعد؛ الإشعارات داخل التطبيق تعمل |

## 28. قائمة تحقق التسليم

- [ ] كل المستخدمين أُنشئوا بأدوارهم الصحيحة وحدود خصم مناسبة.
- [ ] المخازن والأصناف والوحدات مضبوطة، والأسعار مُسعّرة.
- [ ] العملاء مرتبطون بقوائم أسعارهم ومندوبيهم، والحدود الائتمانية محدّدة.
- [ ] الأرصدة الافتتاحية مُدخلة (أصناف/عملاء/موردون/خزائن).
- [ ] بيانات الدخول الافتراضية **دوّرت** ولم تُشارك.
- [ ] نسخة احتياطية حديثة موجودة بعد آخر إدخال بيانات، وتم **تمرين استرجاع ناجح**.
- [ ] ضبط `FCM` إن رُغب في إشعارات الأجهزة.
