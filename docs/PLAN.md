## 1. الحزمة التقنية

| الطبقة       | الاختيار                                                   |
| ------------ | ---------------------------------------------------------- |
| بنية المشروع | Monorepo — pnpm workspaces + Turborepo                     |
| الخادم       | NestJS 11 + Prisma + PostgreSQL (PostGIS) + Redis (BullMQ) |
| لوحة الويب   | Next.js (App Router) + Tailwind + shadcn/ui — RTL أولاً    |
| الموبايل     | Flutter + Drift (SQLite) + Riverpod (Android أولاً)        |
| التخزين      | MinIO (S3) لحزم الأرشيف والصور                             |
| التوثيق      | OpenAPI (ناتج Swagger من NestJS)                           |
| CI           | GitHub Actions (lint + typecheck + test + build)           |

### بنية المجلدات

```
bayan/
├─ apps/
```

## 2. قرارات معمارية (ADR)

> السجلات التفصيلية في [`docs/adr/`](./adr/README.md) — القائمة أدناه ملخّص القرارات الأصلية (كلها مقبولة ومُنفَّذة).

1. **`period_id` على كل جدول transactional من أول migration** — الترحيل (المرحلة 6) بدونه مستحيل لاحقاً.
2. **محرك الحسابات في `packages/shared`** (دوال TS نقية) + **اختبارات ذهبية** تُنفَّر بـ Dart port مطابق في الموبايل — حسابات أوفلاين مطابقة 100%.
3. **ترقيم Offline-safe:** بادئة النوع + كود المندوب + **حجز كتل أرقام مسبقاً للجهاز** (`BP-M03-000127`) + `client_uuid` لكل بيان.
4. **RBAC مركّز:** جدول أدوار/صلاحيات + مصفوفة §4.2 مبنية كبيانات إعداد أولية، مع اختبار لكل خانة.
5. **دفتر حسابات (Ledger) مدين/دائن** من المرحلة 2 لكشوف العملاء والأرصدة الافتتاحية.
6. **الترحيل يُصمَّم مبكراً ويُنفَّذ أخيراً:** حقول الأرشيف (`period_id`, `archived_at`) منذ البداية.
7. PDF عربي RTL: تقييم مبكر (pdfmake بخط مضمّن) في المرحلة 2 قبل بناء الطباعة بالكامل.
8. **نموذج SaaS متعدد الشركات:** النظام يُقدَّم كخدمة لعدة شركات، كل شركة مستأجر (Tenant) بحالة تفعيل، مع **مشرف عام** للبيئة يفعّل/يعطّل الشركات ويشغّل/يطفئ **ميزات النظام (عام أو لكل مستخدم)**.

## 3. المراحل الثماني

### المرحلة 0 — التأسيس (أسبوعان) ✅ مكتملة

- إعداد Monorepo، الأدوات (pnpm، Flutter)، docker-compose (PostgreSQL + Redis + MinIO).
- CI، قواعد lint/format، حزمة `packages/shared` بمحرك الحسابات و اختباراته.
- تحليل المتطلبات مع الإدارة/المحاسب/المخزن (خارج الكود).
- **القبول:** `pnpm build` و `pnpm test` ينجحان من الجذر.

### المرحلة 1 — النواة (5-6 أسابيع) ✅ مكتملة

- **جداول:** users, roles, permissions, item_attributes, units, item_units, price_lists, item_prices, price_history, customers, suppliers, warehouses, stock_balances, stock_movements.
- **API:** مصادقة JWT + RBAC، وحدات القياس (مكامل/وزني 3 خانات)، تسعير يومي للحديد مع سجل تغييرات، عملاء بحدود ائتمانية.
- **Web:** الأصناف، الأسعار (تسعير جماعي)، العملاء، المخازن، المستخدمون.
- **القبول:** تحويل وحدات صحيح، حدود خصم لكل دور قابلة للضبط.

### المرحلة 2 — دورة البيع والشراء (5-6 أسابيع) ✅ مكتملة

- **جداول:** price_statements(+_lines), statement_revisions, purchase__, return__, receipts/payments/cheques, approvals, **ledger_entries**.
- **API:** محرك الخصومات (صنف ← بيان، تحويل تلقائي نسبة↔قيمة، طلب موافقة عند التجاوز)، كشف حساب، مرتجع مرتبط بالبيان الأصلي **بصافيته الفعلية**، حجز كميات المسودات، طباعة A4 + 80مم.
- **Web:** بيان الأسعار، توريد، مرتجع، تحصيل.
- **قبل البدء:** تأكيد الإدارة: تقييم المخزن بآخر سعر شراء؟ + الالتزام الضريبي؟ (§12 من المستند).
- **القبول:** المثال العددي في §13 يمر كما هو.

### المرحلة 3 — الجرد والتقارير (3-4 أسابيع) ← **MVP للمكتب** ✅ مكتملة

- جرد بـ Snapshot وتجميد نسبي، إعادة عد، اعتماد المالك ← تسوية تلقائية.
- تقييم مخزون بآخر سعر شراء + تنبيه "بدون سعر".
- تقارير (مبيعات/خصومات/مرتجعات/مخزون/تدقيق) + Excel/PDF عربي + Dashboard.

### المرحلة 4 — تطبيق المناديب (6-8 أسابيع) ✅ مكتملة

- Flutter: تسجيل جهاز، Delta Sync + retry/backoff، تخزين Drift محلي، إصدار بيان/مرتجع/تحصيل أوفلاين، حالات المزامنة، طباعة بلوتوث + PDF/واتساب، خطة زيارات، عهدة.
- API: قنوات مزامنة وحل تعارضات (تغيّر سعر/رصيد ← "بانتظار المراجعة").
- **القبول:** 30 بياناً في وضع الطيران ثم مزامنة دون تكرار رقم أو فقد.

### المرحلة 5 — التتبع الجغرافي (3 أسابيع) ✅ مكتملة

- وردية فقط (بدء/إنهاء)، تحديث موقع كل 30-120 ثانية بتخفيف عند السكون، خريطة OSM + Route Replay، مطابقة موقع العميل (150م)، تقارير مسافات، موافقة صريحة (نظام 151/2020)، حذف تلقائي بعد 90 يوم.

### المرحلة 6 — الترحيل والأرشفة (3 أسابيع) ✅ مكتملة

- خط أنابيب: فحوصات ← نسخة احتياطية ← تصدير Excel/PDF/JSON + manifest + SHA-256 ← مطابقة ← تأكيد بكلمة ← حذف ← تدوير أرصدة افتتاحية ← سجل.
- عارض أرشيف (بحث وطباعة دون استيراد)، استعادة للمدير، تذكير دوري.

### المرحلة 7 — التجربة والإطلاق (3-4 أسابيع) ✅ مكتملة

- ترحيل بيانات قديمة، تجربة موازية، تدريب، إطلاق تدريجي، اختبار استعادة نسخة احتياطية.

**الإجمالي التقريبي: 30-36 أسبوعاً.**

## 4. MVP والترتيب

- **MVP (بعد المرحلة 3):** الويب الإداري كامل للمكتب — أصناف/أسعار/عملاء/بيانات أسعار/توريد/مرتجعات/تحصيل/جرد/تقارير.
- تأجيل backlog: تارجت وعمولات، عروض أسعار، حاسبات دهان/حديد، ميزان، فاتورة ضريبية إلكترونية، تعدد فروع، iOS.

## 5. المخاطر المعمارية

| الخطر                         | المعالجة                                  |
| ----------------------------- | ----------------------------------------- |
| تكرار ترقيم أوفلاين           | كتل أرقام مسبقة + client_uuid (المرحلة 2) |
| اختلاف حسابات الموبايل/الخادم | اختبارات ذهبية مشتركة TS/Dart             |
| صعوبة الترحيل لاحقاً          | period_id من أول migration                |
| PDF عربي RTL رديء             | تقييم مبكر في المرحلة 2                   |
| صلاحيات معقدة (7 أدوار)       | RBAC مركّز + اختبار لكل خانة المصفوفة     |
